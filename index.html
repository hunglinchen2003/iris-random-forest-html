怎麼把 R Shiny 轉成這個 HTML

Shiny 是一支一直開著的 R。瀏覽器每動一次滑桿，就把四個數字送回 R，R 呼叫 predict(model, newdata)，再把文字送回來。單一 HTML 檔案裡沒有 R，也沒有伺服器，所以不能把 shinyApp() 原樣貼上。

這次沒有用 JavaScript 重新實作隨機森林的訓練。訓練裡的拔靴抽樣與節點搜尋留在 R。搬進網頁的，是訓練結束之後那一座已經長好的森林，以及 R 在預測時走樹、計票的規則。

01用 03_Machine_learning.R 同一段 train() 在 R 裡長出森林。
02getTree() 讀出每一棵樹的切點與子節點，寫進這個 HTML。
03瀏覽器的 predict.js 沿同一條路走樹、計票，得到種類。

對應的檔案是 export_model.R（訓練、匯出、核對）、predict.js（走樹與投票）、index.template.html（這個版面）。執行匯出腳本後得到現在開啟的 index.html。模型嵌在檔案裡，打開即可預測，不需要再連上 R。

訓練呼叫與 Shiny 相同

03_Machine_learning.R 在建立介面之前先做這一段。匯出腳本使用同一順序：先 set.seed(123)，再 trainControl(method = "cv", number = 10)，再 train(Species ~ ., data = iris, method = "rf", trControl = ctrl)。中間沒有其他會消耗亂數的步驟。

set.seed(123)
data(iris)
ctrl <- trainControl(method = "cv", number = 10)
model <- train(Species ~ ., data = iris, method = "rf", trControl = ctrl)
accuracy <- mean(model$resample$Accuracy)

method = "rf" 使用 randomForest::randomForest。這次呼叫沒有另外指定 ntree、nodesize 或 importance，所以沿用套件預設：500 棵樹、分類的 nodesize = 1、每棵樹用拔靴樣本。實際棵數與選到的 mtry 寫在左欄，也寫在頁尾的版本紀錄。

caret 預設會試三個 mtry。四個預測變數、分類問題時，caret::var_seq(p = 4, classification = TRUE, len = 3) 是 floor(seq(2, 4, length.out = 3))，也就是 2、3、4。每一個候選都做 10 折交叉驗證。caret 採用平均準確率最高的那個，記在 model$bestTune，再用這個 mtry 與全部 150 筆重訓最終森林。網頁裡的樹是這座 model$finalModel，不是某一個交叉驗證折裡的樹。

滑桿怎麼對到四個變數

Shiny 的 server 把四個滑桿組成一列資料，欄位名稱必須是模型公式裡的名稱，然後呼叫 predict(model, newdata)。caret 的 rf 預測會進到 predict(finalModel, newdata)，所以兩邊用的是同一座森林、同一組票數。沒有平手時，兩個呼叫印出的種類相同。平手時它們各自抽一次亂數，印出的文字可以不同；這個網頁改為把平手標出來。

預測公式

一棵樹

randomForest::getTree() 的每一列是一個節點。split var 為 0 表示葉子。內部節點記錄分割變數、切點、左子節點與右子節點。randomForest 的預測往左的條件是特徵小於等於切點。網頁使用同一個條件。

node ← 根節點
while 這個節點不是葉子:
    v ← split var
    if x[v] ≤ split point:
        node ← left daughter
    else:
        node ← right daughter
這棵樹投票給葉子上記錄的種類

子節點編號有一次純索引轉換：R 的列號從 1 開始，終端節點的子節點寫 0；網頁改成從 0 開始，終端改記 −1。比較的數字沒有改。切點不以十進位小數四捨五入存檔，而是把 R 的 IEEE-754 倍精度浮點數以 little-endian 位元組做 base64。瀏覽器解回同一個 double 再和 x[v] 比較，避免切點剛好等於輸入時走錯邊。

這次森林共有 個節點，平均每棵樹 個節點。

500 棵樹如何變成一個種類

每一棵樹投一票。vote(c) 是投給種類 c 的樹數。randomForest::predict() 的分類規則寫在套件說明裡：勝出的種類是「票數比例 / cutoff」最大的那個。比例是 vote(c) / ntree。預設 cutoff 是每個種類 1 / k。k = 3 時，三個 cutoff 都是 1/3，ntree 也相同，所以比較 vote(c) / cutoff(c) 的順序就是比較票數。

vote(c) = 投給種類 c 的樹數
score(c) = (vote(c) / ntree) / cutoff(c)
預測種類 = argmax score(c)

票數完全相同時，randomForest 會用亂數在並列的種類裡挑一個，所以 Shiny 若遇到平手，重新整理可能印出不同種類。這個網頁不算那一次亂數。它把所有並列第一的種類都標成平手。沒有平手時，顯示的種類與 predict() 相同。百分比只放在票數旁邊方便閱讀，判斷用的是票數，不是四捨五入後的百分比。

變數重要性

Shiny 呼叫 importance <- varImp(model)，長條圖的 y 是 importance$importance[, 1]。這次 train() 沒有設 importance = TRUE，所以 randomForest::importance() 的那一欄是 MeanDecreaseGini，不是排列重要性。caret 再把它縮放到 0 到 100：

shifted(j) = Gini(j) − min(Gini)
I(j) = shifted(j) / max(shifted) × 100

最小的變數變成 0，最大的變成 100。左欄長條使用這個 I(j)，由大到小排列，顏色 #B2182B。

變數MeanDecreaseGini縮放後 I(j)

畫面上的 Average Accuracy

如何確認公式一樣

核對分三層，而且預測那層用的就是網頁裡的 predict.js，不是另外寫一支只在 R 裡自比自的迴圈。

  1. 用 R 依照 getTree() 的列，走 5 筆資料的全部樹，與 predict(finalModel, predict.all = TRUE) 的每一棵樹輸出比較。這確認匯出的節點沒有讀錯。
  2. 把 predict.js 放進 R 的 V8 引擎，對下面這批輸入計算票數，與 predict(finalModel, type = "vote", norm.votes = FALSE) 的整數票數比較。
  3. 沒有平手的列，種類要同時等於 Shiny 使用的 predict(model, newdata) 與 predict(finalModel, newdata)。平手的列則確認 R 印出的種類是並列第一的其中一個。

驗證輸入有四部分：全部 150 筆訓練資料、滑桿範圍內的網格（）、以 set.seed(456) 在滑桿範圍內抽的 200 點，以及 Shiny 預設值和兩個滑桿角落。列數是訓練 、網格 、隨機 、定錨 ，合計 。定錨列可能與網格重複，合計是送進 predict() 的列數。

網頁載入後會用同一支 predictCase() 把下表再算一次。右欄的 JavaScript 票數如果與 R 不同，上方提示會變成未通過。

界限與如何重做這個檔案

重新執行 Shiny 腳本時，若 R、caret 或 randomForest 的版本不同，set.seed(123) 仍可能長出另一座森林。這個 HTML 固定的是這一次訓練的樹。滑桿不會在瀏覽器裡重訓。平手也不做 R 內部的那一次亂數抽取。

要重做這份網頁，在此資料夾用已安裝 caret、randomForest、jsonlite、V8、ggplot2 的 R 執行 Rscript export_model.R。腳本會重訓、再跑上述核對，通過之後才覆寫 index.html。頁尾是產生這個檔案的環境。
